# 11. push_swap との関係

## ここまでで理解したこと

循環型配列で学んだこと。

- `head` は次に取り出す場所
- `tail` は次に入れる場所
- `push()` は `tail` に書いて `tail` を進める
- `pop()` は `head` から読んで `head` を進める
- `% size` は配列外に行かないために使う
- 1マス空けるのは、空と満杯を区別するため
- `is_full()` は「tailの次がheadか」を見る
- `is_empty()` は `head == tail` を見る
- 空なのに `pop()` するとゴミを取り出す

## push_swap に戻る判断

循環型配列の理解は進んだ。

ただし、これ以上キューを作り込むより、push_swap に戻る方がよい。

理由。

```text
学習用の循環型配列
```

と

```text
push_swap の本体
```

は別物だから。

## push_swap で使える考え方

push_swap では、操作によってスタックが回転する。

例えば、

- `ra`
- `rb`
- `rra`
- `rrb`

は「先頭や末尾の位置が動く」と考えられる。

ここで循環型配列の考え方が使える。

```text
物理的に配列を全部ずらすのではなく、
head の位置を変える
```

という発想。

## ただし注意

push_swap で必ず循環型配列を使う必要はない。

実装候補は複数ある。

- 配列を実際にずらす
- linked list を使う
- head index を持つ配列にする
- 循環バッファ的に扱う

今は、どれが正解かよりも、

```text
自分の実装で操作を説明できるか
```

が大事。

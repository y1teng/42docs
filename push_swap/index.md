# push_swap

> **2人チームプロジェクト。** 2つのスタックと11種類の操作だけを使って、できるだけ少ない手順で整数列をソートするCプログラムを書く。

## この課題で何を学ぶか

- アルゴリズムの計算量（Big-O）を**実際の操作数**で体感する
- 同じ問題でも、アルゴリズムによって必要な操作数が桁違いになることを知る
- 複数のアルゴリズムを実装し、入力の「乱雑さ」によって使い分ける設計をする
- 「配列を直接書き換える」のではなく「決まった操作の組み合わせだけで状態を変える」という制約下で考える

## 概要

```
スタック a: [2, 1, 3, 6, 5, 8]  ← 引数として受け取る（上が先頭）
スタック b: []                    ← 最初は空

目標: stack a を昇順（小さい順）に並べる
手段: 11種類の操作を使う（できるだけ少なく）
```

プログラムは操作の列を **stdout** に1行ずつ出力する。

```
./push_swap 2 1 3 6 5 8
sa
pb
...
```

## エラー処理

以下の場合は `Error\n` を **stderr** に出力してプログラムを終了する：

- 引数が整数でない（`"one"` など）
- 重複する値がある（`3 2 3` など）
- 整数の範囲外

引数が何もない場合は何も出力せず正常終了。

## 実装前の疑問リスト

Simple版（選択ソート）を書き始める前に、勘違いしたまま突っ走っていた点。

### `head` と `top` は同じもの？

**勘違い**：「headとtopは同じもの」「headが動くのはおかしい」と感じていた。

**実際**：`head` は「配列の中で今どこが正面(top)か」を示す**動くインデックス（付箋）**。`top` はその `head` が指している**値**（`data[head % capacity]`）。配列そのもの（＝椅子の並び）は動かない。動くのは付箋の位置だけ。

| 用語 | 意味 |
|---|---|
| `head` | 「今どこが正面(top)か」を示すインデックス。`ra`/`rra`で動く |
| `top` | `head` が指している値（`data[head % capacity]`） |
| 椅子番号（たとえ） | 配列のインデックスそのもの。固定・不変 |
| 座っている人（たとえ） | その椅子(インデックス)に入っている値 |

### `pb` で送った値は配列から消える？

**勘違い**：`pb` で値を送ったら、配列から物理的に消える（メモリから消える）と思っていた。

**実際**：`data` の中身は書き換えられない。値は残り続ける。`size` が `op_push` のたびに `--` されるだけ。「消えた」とは、**head と size が作る論理的な範囲（有効範囲）の外に出た**という意味であって、帳簿上の除外にすぎない。物理削除ではない。

### 配列ソートのロジックをそのまま使える？

**勘違い**：挿入ソートや選択ソートの教科書実装をそのまま持ってこられると思っていた。

**実際**：配列ソートは `arr[j] = arr[i]` のように任意の位置へ直接書き込める。しかしスタックソート（push_swap）は `sa, ra, pb` など決まった11操作しか使えず、任意位置への直接書き込みは不可能。「配列ソートのロジックの流用」ではなく「アルゴリズムを操作列へ翻訳する」という発想の転換が必要だった。

## 詰まったポイントと解決策

Simple版を `checker` で `OK` にするまでに見つけたバグ。

| # | 症状 | 原因 | 直し方 |
|---|---|---|---|
| 1 | `sort_find_min_index` が `head` を書き換えてしまう | ループ内で `head++` していた（本来は読むだけでよい） | `head` を変更せず、`(head+count)%capacity` で仮想的に読むだけにした |
| 2 | `min_idx` が常に同じ値になる | `count` を使わず固定値を代入していた | `min_idx = count`（見つかった瞬間の`count`を保存）に修正 |
| 3 | `op_pb(&a, &b)` で向きが逆 | `dst, src` の引数順を勘違いしていた | `op_pb(&b, &a)` に修正。`dst`=積まれる側、`src`=取り出される側 |
| 4 | ループが早期終了する | `size` はループ中に減っていく値なのに、終了条件にそのまま使っていた | `origin_size` を別に保存し、それをループ条件に使う |
| 5 | 表示ロジックのインデックス計算が2種類混在していた | `head`ベースと生インデックスベースがズレていた | `data[a_top]` に統一 |
| 6 | 4回目以降、同じ値が2回bに送られる／別の値が消える | **`op_rotate`(`ra`)** で、`size < capacity` のとき、はみ出す1マスに古いゴミ値が残ったまま読まれていた | 下記「核心バグ」参照 |
| 7 | `print_op` がリンクエラー（`undefined reference to ft_printf`） | `ft_printf` は `libftprintf` という別ディレクトリのソース。コンパイル対象に含めていなかった | `gcc *.c libftprintf/*.c ...` のようにソースごとコンパイル対象に加えた |
| 8 | ビルドしても実行結果が何も出ない | `sa`等の各操作関数に `print_op` 呼び出しを追加し終えていなかっただけ | `op_s.c`, `op_p.c`, `op_r.c` の各操作関数末尾に `print_op(OP_XX)` を追加して解決 |

### 核心バグ：`op_rotate` のゴミ混入

`size < capacity`（＝一部の要素が既にpop済み）の状態で `ra` を呼ぶと、有効範囲全体が1マスぶんスライドする。このとき「新しく範囲に入ってくるマス」（`head + size` の位置）には、まだ古い・無効なゴミ値が残ったままだった。`sort_find_min_index` はそのゴミ値を「まだ残っている値」として誤って読んでしまっていた。

```c
void op_rotate(t_stack *n)
{
	int new_pos;

	new_pos = (n->head + n->size) % n->capacity;   // これから範囲に入ってくるマス
	n->data[new_pos] = n->data[n->head];            // 今のtopの値をそこにコピー
	n->head = (n->head + 1) % n->capacity;          // headを進める
}
```

「コピー → head更新」の順番が重要。円環バッファの「データを動かさない」利点は一部失うが、正しさを優先した。

## 実装して気づいたこと

- この `op_rotate` の修正はアルゴリズム（選択ソート）に依存しない、`op_rotate` 自体の修正。よって挿入ソートなど他アルゴリズムでも恩恵を受ける。
- `op_push`（pa/pb）側は、新しく増えるマスに必ず値を書いてから `size++` しているため、そもそもこのゴミ混入問題は起きない。
- **`op_reverse_rotate`（rra/rrb/rrr）にも同種のバグがあることを実際に確認した。** `size == capacity`（スタックが満杯）の間は正しく動くが、`size < capacity` の部分状態では、末尾の値ではなく無効なマスの値を先頭に読み込んでしまう。

  検証コード（`capacity=4, size=2, head=1`、有効範囲は `{10, 20}` で `rra` は `{20, 10}` になるべき）:

  ```
  [partial] before window = 10 20   (expect rra -> 20 10)
  [partial] after rra: head=0 -> 99 10   ← 99 はゴミ（未修正）
  ```

  原因は `op_rotate` と逆で、コピーの向きが `new_pos ← head` になっており、部分状態では `head` 側（＝新しく先頭になる、まだ有効範囲外のマス）にゴミが入っている。`op_rotate` の修正と対称に、「末尾の値を新しい先頭マスへコピーしてから `head` を戻す」向きに直す必要がある。**未修正・要対応。**

- フラグ（`--simple` 等）は `argv` の先頭から `--` で始まる間だけ読み進め、`--` で始まらない引数が出た位置を `num_start` として記録する方針にした。フラグの中身による分岐（`strategy` で処理を切り替える部分）は Medium/Complex 実装後に着手する。

## 人に説明するなら

push_swap は、「2つの箱（スタックa, b）と、決まった11個の操作しか使えない状況で、できるだけ少ない手順で数字を並べ替えるパズル」。配列のように好きな場所に直接書き込むことはできず、「先頭2つを入れ替える」「先頭を隣の箱に移す」「先頭を末尾に送る」という限られた操作の組み合わせだけで、目的の並びに持っていく必要がある。

内部的には、スタックは「頭出し用の付箋（`head`）」を持った固定長配列（循環バッファ）として表現されていて、値そのものを動かさずに付箋の位置を動かすことで `ra`/`rra` を実現している。詳しくは[コードの説明](./code-walkthrough)と[循環型配列 教材](./circular-buffer-00-index)を参照。
